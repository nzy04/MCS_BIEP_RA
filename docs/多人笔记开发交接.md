# 多人笔记与昵称功能交接

状态：实现和本地验收完成，可与 DeepSeek 审核代码联合发布。本任务未推送、未部署，也未修改远端论文数据。

## 已完成的行为

- 同论文按规范化来源链接（arXiv abs/pdf/html/版本、DOI、OpenReview 等）及规范化完整标题归组；保留各份独立的 note UUID、内容、附件和版本。旧数据无需迁移即可展示。
- 列表每篇论文下提供全部作者的笔记入口；搜索一名作者仍保留同论文其他人的笔记入口。统计区区分论文数量和笔记份数，贡献者按 GitHub 身份计数。
- 阅读页切换同论文其他人的笔记；「添加我的笔记」以新的 UUID 复用论文基本信息，正文留空。已发布笔记只能由本人修改，服务端也检查归属。
- 右上角名字旁的铅笔打开昵称表单；留空使用 GitHub 名称，允许不同账号重名，并继续显示原 GitHub @login。
- PUT /api/profile 写入 data/authors/{GitHub数字ID}.json，将本人历史笔记 JSON、索引和 Markdown 署名在一次 Git 提交中同步；旧 authorLogin 和新的 authorId 均可识别。内容、更新时间和笔记 revision 不因改名变化。
- 昵称保存使用不可变 head 读取和非强制分支更新，遇到并发提交重读合并，最多尝试三次。历史文件不完整时整体失败，不发布部分改名。
- GET /api/session 从仓库读取当前昵称，重新登录和刷新仍生效；commitNote 在每次提交尝试中读取最新资料，即使审核任务中暂存的是改名前身份，也使用最新昵称。
- 登录后的分享人随账号昵称统一；本地未登录体验仍可填写分享人。打开上传页时先检查已有草稿，避免自动填昵称触发空白自动保存覆盖待恢复内容。
