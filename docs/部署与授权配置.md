# MCS_BIEP 初版部署与授权配置

这份说明面向维护者。组员配置完成后只使用网站，不需要创建自己的访问令牌。

## 1. 已确定的信息

- 网站名称：MCS_BIEP。
- 目标仓库：nzy04/MCS_BIEP_RA，公开，默认分支 main。
- 免费托管：Cloudflare Workers 的静态资源和轻量接口，同一域名。
- 内容存储：GitHub 仓库。无需额外论文数据库。

## 2. Cloudflare 账号与首次部署

维护者在 Cloudflare 官方网站注册账号并自行完成账号验证。

本机运行：

```bash
pnpm exec wrangler login
pnpm build
pnpm exec wrangler deploy
```

首次可以保留 `wrangler.jsonc` 中空白的 GITHUB_OWNER，先得到网站域名并体验本地模式。部署后记录类似 `https://mcs-biep-ra.<账户子域>.workers.dev` 的真实地址。

## 3. 注册 GitHub App

GitHub Settings → Developer settings → GitHub Apps → New GitHub App。

- App 名称：选择尚未被使用的名称，例如 MCS-BIEP-RA-加个人后缀。
- Homepage URL：上一步真实网站地址。
- Callback URL：`https://实际域名/api/auth/callback`。
- 关闭不使用的 Webhook。
- Repository permissions：Contents 选择 Read and write；保留默认 Metadata 读取。
- 不申请 Workflows、Administration 或无关仓库权限。
- 供不同 GitHub 账号的组员登录时，应用注册需要公开。GitHub 当前限制个人私有应用只能由创建者登录；公开应用注册不会自动给访问者仓库写权限。
- 采用用户授权流程。初版会话最长 8 小时，过期后重新登录，不实现长期刷新令牌保存。
- 安装 App 时只选择 MCS_BIEP_RA 仓库。

创建后获得 Client ID，并生成 Client secret。密钥直接保存在本机或 Cloudflare Secret 中，不发到聊天、不提交仓库。

GitHub App 的注册和安装需要维护者本人确认权限。此项目代码不会自动替维护者注册高权限应用。

## 4. 配置服务端密钥

修改 `wrangler.jsonc` 的非敏感参数：

```text
GITHUB_OWNER = nzy04
GITHUB_REPO = MCS_BIEP_RA
GITHUB_BRANCH = main
GITHUB_CLIENT_ID = 实际 Client ID
```

使用以下命令按提示输入 Secret，不把 Secret 放在命令行参数中：

```bash
pnpm exec wrangler secret put GITHUB_CLIENT_SECRET
pnpm exec wrangler secret put SESSION_SECRET
```

SESSION_SECRET 使用密码管理器生成至少 32 字符的随机值。完成后重新部署。

本地联调时，可复制 `.dev.vars.example` 为 `.dev.vars`，填入本机 Secret；该文件已经加入 `.gitignore`。本地 Callback URL 应与实际使用的请求入口一致。

## 5. 组员权限

仓库 Settings → Collaborators 中邀请组员，并授予需要的写入权限。组员在网站点击 GitHub 登录，授权后返回网站。是否能发布同时取决于成员的仓库权限和 App 权限。

公开阅读无需登录。授权成功但没有写权限的用户可以阅读和本机保存，发布接口会拒绝仓库写入。

## 6. 上线验收

为节省构建次数，在 Cloudflare Settings → Builds → Build watch paths → Exclude paths 中加入 `data/**`、`papers/**`、`assets/uploads/**`。论文通过接口从仓库读取，内容更新不需要重新构建前端。GitHub CI 已忽略只涉及这些目录的提交。

1. 用真实 GitHub 账号登录，确认回调正确、退出有效、过期后可重新登录。
2. 上传一份测试 DOCX，确认标题、正文与图片，再在模板中修改备注。
3. 点击发布，检查返回的 GitHub 提交；笔记 JSON、Markdown 和图片应在同一次提交中。
4. 换一个浏览器读取正式笔记，确认内容来自仓库。
5. 两人修改同一版本，后发布者应收到冲突提示，原内容不能被静默覆盖。
6. 检查无写权限账号、错误授权状态与超限附件的错误提示。
7. 检查手机阅读、实际网络访问、CPU/请求额度与附件体积。

浏览器解析不调用模型。若将来增加大模型，另行选择服务和预算，并在发布前继续保留人工确认。
